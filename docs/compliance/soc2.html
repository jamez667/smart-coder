Scope and limitations

This pack inspects source-controlled artifacts only. It cannot observe running infrastructure, cloud provider configuration, identity provider settings, HR processes, vendor agreements, or incident records. Controls depending on those are reported Unknown by design and appear in the manual-evidence worklist. Roughly five of the thirty-three common-criteria points yield deterministic source evidence. A passing result here is evidence toward a control, never an attestation of compliance.

CC6.1gapLogical access — credentials are not committed to source

The entity implements logical access security software, infrastructure, and architectures over protected information assets to protect them from security events. Credentials committed to version control defeat every downstream access control, because the repository history retains them after deletion.

all-of: worst of 5 check(s) is gap

Remediation: Rotate any exposed credential immediately — deleting the file is not sufficient, as the value remains in git history. Then add the path to .gitignore and adopt a secret scanner as a pre-commit hook.

any-of: no mechanism evidenced, and 2 of 2 check(s) were indeterminate

Obtain: Add a dependency audit step (cargo audit, pip-audit, npm audit, Dependabot) to CI.

CC6.1-LOCALunknownLocal secret hygiene — untracked credentials in the working tree

Secrets present in a working directory but excluded from version control are not committed, and are therefore outside the strict scope of CC6.1. They remain an exposure on developer machines and in backups, and are one forced add away from entering history permanently.

all-of: worst of 1 check(s) is unknown

Obtain: Prefer a managed secret store or an OS keychain over a file on disk. Where a local file is unavoidable, keep it gitignored (as here), restrict its permissions, and rotate on any suspicion of exposure.
