Scope and limitations

This pack inspects source-controlled artifacts only. CIS v8 governs an enterprise estate: endpoint inventory, account management, network infrastructure, malware defences, physical media and security awareness. None of that is visible from a repository. What this pack evidences: the software-development safeguards (Control 16), configuration-as-code (Control 4), audit logging (Control 8), data protection (Control 3), and continuous vulnerability management (Control 7) — as they appear in source. Implementation Groups (IG1/IG2/IG3) are not modelled: a safeguard's group depends on organizational size and risk, which this tool cannot know.

CIS-3.11unknownEncrypt sensitive data at rest and in transit

Encrypt sensitive data in transit and at rest on servers, applications and databases, using algorithms and key lengths that remain fit for purpose.

all-of: worst of 3 check(s) is unknown

Evidence to obtain
  • Cloud provider console exports or API queries showing KMS/encryption enabled on active databases and storage buckets
  • TLS certificate configuration reports from an external assessor or scanning tool (e.g., SSL Labs) for public endpoints
  • Data classification matrix defining which data types require encryption

Usually held by: Cloud Infrastructure Team / Security Engineering

What an auditor will probe: How do you ensure encryption is consistently applied to newly provisioned storage, and how do you verify the cryptographic standards remain current?

Obtain: Enforce TLS on external endpoints and enable storage encryption; never disable verification.
